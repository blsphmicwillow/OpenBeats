# Theme QA — OpenBeats 1.0.5

Generated by `scripts/qa-visual.mjs`. **Scope: 22 combinations** — the 11 built-in
themes in both interface modes (`classic`, `modern`), captured from the Vite web
build at 1440×900.

> **Why 22 rows, not 96.** The requested matrix was 6 themes × 4 modes × 4 background
> images. This build has **11 themes**, **2 interface modes** and **no background-image
> feature at all** — there is no wallpaper/bgImage setting and the only file picker in
> Settings imports theme JSON. A 96-row table would have shown screenshots of a
> feature that does not exist, so it was not produced. See `docs/AUDIO_CLIPS.md` and
> the 1.0.5 release notes for what does ship.

## Method

- Foreground colours are read from the live page via a probe element using the
  theme tokens (`--text`, `--dim`, `--accent-text`, `--accent`).
- Background colours are sampled from each screenshot (median of an 11×11 patch)
  at four regions: *workspace*, *browser panel*, *top bar*, *hint bar*.
  Sampling the real pixels is what makes the four translucent glass themes honest.
- `--text` is checked against all four surfaces. `--dim` is checked only against
  chrome (browser panel, top bar, hint bar) because that is where secondary text
  renders; clip labels use `--clip-text` over per-clip colours instead.
- No glyph pixels are sampled: antialiased text cannot yield a WCAG ratio. WCAG 2.x
  relative luminance is applied; body text needs 4.5:1, large/UI 3:1.
- The in-app splash overlay is waited out before capture. It is a full-viewport
  branded screen; measuring it would grade the splash instead of the studio.
- This drives Chromium against the web build, not the Tauri WebKitGTK window, so it
  validates shared CSS only. Native window chrome and native-only surfaces are out
  of scope and are not claimed here.

## Limitations

- Background patches are four fixed points; a text element sitting on an unusual
  surface is not individually measured. The token pairs cover body, dim and accent text.
- Glass themes are measured with their real translucency, but only at the default
  window size and with no content behind the panels beyond the app’s own gradient.
- Screenshots use the seeded Tutorial project, so clip colours are present; changing
  project content does not change the theme tokens being measured.
- Pixel patches include any text that falls inside the 11×11 window at that point;
  the median suppresses it but a very dense region can shift the sampled colour.
